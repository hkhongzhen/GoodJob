## 本次会话做了什么

### 1. 发信前邮箱验证（已完成，已提交 `18341f4`）
移植自 Arlo 项目的 "Verify emails" 功能：

- **两层验证**：免费预筛（语法 / MX 记录 / 一次性域名 / 角色前缀）+ 可选第三方 API（ZeroBounce / NeverBounce / Reoon power 模式）。
- **预筛自动执行**：候选入库时、打开搜客清单时自动跑，不产生费用，不调第三方。
- **手动验证才花 API 配额**：点「验证」按钮才调第三方；只有预筛结果的邮箱在手动验证时会补调 API。
- **结果缓存**：`email_verifications` 表按「团队+邮箱」存，默认 30 天有效，避免重复计费。
- **发信拦截**：`dispatchOutboundEmail` 统一守卫；默认拦截 INVALID 和 DISPOSABLE，可在「邮件中心 → 邮箱设置 → 邮箱验证」配置（仅管理员）。
- **入口**：搜客清单批量栏「验证邮箱」、开发信工作区「收件邮箱」旁验证按钮、客户详情/抽屉、客户列表批量栏、发信批次放行前自动验证。
- **发信资格灯**：新增「邮箱未通过验证」状态，自动改用备用邮箱。

### 2. 搜客界面恢复 + 四选一（已完成，已提交 `ada2e7a`）
- 去掉 `#lead-finder` 的 `lf-cli-only` CSS 隐藏类（3.0.1 版本加的，恢复完整界面）。

## 本机开发环境

- **后端**：`node scripts/run-with-profile.mjs development npm run dev:mysql --workspace backend`，端口 4190，`tsx watch` 自动重载。
- **前端**：`npm run dev --workspace frontend`（Vite 5188，热更新）；生产构建 `npm --prefix frontend run build`，后端从 `frontend/dist` 提供。
- **数据库**：本机 MySQL `goodjob_crm_dev`（连接串在 `.env.development.local`，需 `APP_DATABASE_PROFILE=development`，run-with-profile 脚本会自动带上）。
- **测试**：`node ../scripts/run-with-env.mjs NODE_ENV=test npx tsx src/<file>-test.ts`（在 backend 目录）。
- **Runner**：`goodjob-runner pair/doctor/start`，配置在 `~/.goodjob/runner.json`。

## 环境现状与坑

- **Runner 配置指向线上**：`~/.goodjob/runner.json` 连的是 `https://goodjob.360sanit.com`，不是本机 4190。本机配对会覆盖线上配置；要并存需用 `GOODJOB_RUNNER_CONFIG` 分文件。
- **没有配置任何数据源 Key**：`provider_connections` 表为空，标准/超级搜索不可用，只能 CLI 获客。
- **AI 模型 API 未配置**：`ai_model_configs` 为空；开发信来源设了 "ai" 但没 API，建议改 "cli"。
- **机器上 CLI**：PATH 里有 codebuddy；~/.goodjob/runner.json 显示此前识别到 workbuddy + claude，无 codex。`goodjob-runner` 命令可能未 link。
- **数据库写操作注意**：测试会写开发库；验证记录进 `email_verifications` 表。
- **凭据加密**：`PROVIDER_CREDENTIAL_KEY` 需在 .env 设，生产必填 ≥32 字符。
